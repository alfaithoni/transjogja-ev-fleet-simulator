# TransJogja EV Fleet Simulation

Discrete-event simulation (with a Monte Carlo layer) of full-fleet
electrification for the TransJogja bus rapid transit network (Yogyakarta,
Indonesia), used to evaluate SPKLU (public EV charging station) location,
capacity, and charging-mechanism scenarios. This repository accompanies:

- **Thesis (Bahasa Indonesia + English abstract):** [`TA-STI-template-1.0/`](TA-STI-template-1.0/) — see `TA.pdf`
- **Conference paper (English, IEEE format):** [`paper/`](paper/) — see `paper.pdf`

## What's in this repo (and what isn't)

This is a cleaned-up copy of the development repository, prepared for
someone who wants to **run the simulation themselves** rather than dig
through the full development history. Removed on purpose:

- `data/results/` and `data/raw/` — hundreds of megabytes of per-scenario,
  per-day raw output generated by running the scripts below. Not shipped
  because they're regenerable, not because they're secret; run
  `scripts/run_monte_carlo.py` to recreate them for any scenario.
- Ad-hoc development scripts (`scratch/`, `lab/`, one-off debug/trace
  scripts at the repo root) — these were exploratory tools used during
  thesis development, not a maintained interface. The scripts kept under
  `scripts/` are the ones that correspond to what's described in the
  thesis methodology (Bab IV/V).
- `context/` — internal working notes used with an AI coding assistant
  during development (requirements, architecture notes, task breakdowns).
  Not needed to run or understand the simulation itself.
- `optimize/` (GA and Bayesian optimizers) is **kept** for completeness,
  but note that the thesis's final scenarios (Bab VI) do **not** use
  automatic location optimization — see Batasan Masalah (Bab I) and
  `optimize/README.md`. It's included because the code exists and works,
  not because it feeds the reported results.

## Running a scenario

Every scenario used in the thesis is a JSON file under `data/scenarios/`
(e.g. `s28_s17b_extra_bus_scaled_infra.json` corresponds to "S28" in
Bab VI). Two ways to run one:

**Single simulated day** (fast, useful for sanity-checking a scenario):

```bash
python scripts/run_simulation.py --scenario-file data/scenarios/s28_s17b_extra_bus_scaled_infra.json
```

Prints a per-route summary and writes
`data/results/simulation_result_<scenario_id>.json`.

**N-day Monte Carlo aggregate** (this is what the thesis actually
reports — every headway/degradation number in Bab VI is a mean over
N=100 simulated days, not a single run):

```bash
python scripts/run_monte_carlo.py --scenario-file data/scenarios/s28_s17b_extra_bus_scaled_infra.json --n-days 100
```

This prints `avg_headway_mean`, `avg_degraded_routes_per_day_mean`, and
related aggregate metrics, and writes them to
`data/results/mc_<scenario_id>.json`. **Compare the output against the
matching `scenario_id` row in `data/comparison_table_stochastic.csv`** —
that CSV is the exact aggregate table the thesis's figures and tables
are built from. With the same `--seed-base` (default 42, matching what
was used originally), the numbers should land within simulation noise of
the published values; N=10 already lands within about 1% of the reported
headway for S28, for example.

Key scenario IDs referenced in the thesis, if you want to reproduce
specific results without reading every file in `data/scenarios/`:

| Scenario ID | Thesis label | What it tests |
|---|---|---|
| `s17b_probabilistic_4loc_prop` | S17b | 4-site baseline, proportional capacity |
| `s28_s17b_extra_bus_scaled_infra` | S28 | +12% capacity over baseline |
| `s30_s17b_extra_bus_buffer_mid` | S30 | +7% capacity over baseline |
| `s31_s17b_dynamic_v1` | S31 | Dynamic (time-aware) charging policy, no added hardware |
| `s32_s17b_dynamic_v2` | S32 | Dynamic (time+queue-aware) charging policy |
| `s33_ultimate` | S33 | S28 infrastructure + S31 algorithm combined |
| `s15_probabilistic_1loc_n20` ... `s24_probabilistic_1loc_n19` | S15, S19–S24 | Single-station capacity sweep (regime shift) |

## Generating graphs

```bash
python scripts/generate_thesis_graphs.py
```

Writes four charts to `data/results_figures/` (regime shift, headway
comparison, degraded-routes comparison, location/allocation comparison),
built directly from `data/comparison_table_stochastic.csv`.

**Important scope note:** the polished figures embedded in the thesis
PDF (`TA-STI-template-1.0/images/fig_*.png`) were produced ad hoc during
thesis writing, and their generation code was not kept as reusable
scripts in this repository. `generate_thesis_graphs.py` reconstructs the
four most-cited comparisons from the same underlying data so the
substantive numbers and trends can be verified independently — the
values will match, but the styling (fonts, colors, exact layout) will
not be pixel-identical to the thesis PDF. The remaining thesis figures
(spatial/temporal demand maps, Monte Carlo convergence curve, 14-day
resilience trace, per-route deviation table) would need their
corresponding raw data regenerated via `run_monte_carlo.py` with
per-day/per-route logging enabled; that plumbing is not currently
wired up as a single script.

## Interactive dashboard

```bash
python dashboard/app.py
```

Serves a local visualization of route/bus/SPKLU state per scenario, as
described in Bab V of the thesis. Open the printed local URL in a
browser.

## Running tests

```bash
python -m pytest tests/
```

**Known state:** 10 of 17 tests pass. The 7 failures are in
`test_battery.py` and target the early `k1`/`k2` heuristic battery model
mentioned in Bab IV as a discarded intermediate step — that model was
superseded by the Mamarikas et al. rational-polynomial $EC(v)$ model
before the thesis's final scenarios were run, and the corresponding test
cases were never updated or removed. They're a record of that
transition, not a regression in the current simulation; the current
model's behavior is exercised indirectly by `run_simulation.py` and
`run_monte_carlo.py` above.

## Compiling the thesis and paper

Both use XeLaTeX + Biber (not pdfLaTeX + BibTeX). If you use VS Code with
the LaTeX Workshop extension, add this recipe to your settings:

```json
"latex-workshop.latex.recipes": [
    { "name": "xelatex -> biber -> xelatex*2",
      "tools": ["xelatex", "biber", "xelatex", "xelatex"] }
]
```

Or from the command line, in `TA-STI-template-1.0/` (thesis) or `paper/`
(conference paper):

```bash
xelatex -interaction=nonstopmode <file>.tex
biber <file>          # thesis only; paper.tex uses a plain thebibliography
xelatex -interaction=nonstopmode <file>.tex
xelatex -interaction=nonstopmode <file>.tex
```

The thesis (`TA.tex`) requires the Times New Roman font to be installed
on your system (via `fontspec`) and a complete LaTeX distribution
(`texlive-full` on Linux, MacTeX on macOS, or TeX Live/MiKTeX on
Windows) — a minimal install will be missing packages like `tracklang`
and `biblatex-chicago`. The paper (`paper.tex`) compiles with a standard
`pdflatex` install and the bundled `IEEEtran.cls`/`IEEEtran.bst`.

## Data dictionary (quick reference)

| File | What it is |
|---|---|
| `data/routes.json` | The 20 TransJogja corridors: stops, inter-stop distances, bus counts, target headways |
| `data/bus_spec.json` | Battery capacity and energy-consumption model parameters |
| `data/spklu_locations.json` | Candidate/assigned charging station locations |
| `data/scenarios/*.json` | One file per simulated scenario (config passed to `GlobalSimulator`) |
| `data/comparison_table_stochastic.csv` | The aggregate N=100 results table everything in Bab VI is built from |
| `data/headway_vs_dishub_target.csv`, `data/headway_deviation_summary.md` | Per-route headway vs. the operator's published targets |
| `data/dashboard_traces/` | Small sample traces used by the dashboard |

## Academic context

This is thesis and conference-paper research software for the Bachelor's
program in Information Systems and Technology, Institut Teknologi
Bandung. It is not an official TransJogja/Dishub DIY product. Route and
operational data were provided by the author for research purposes.
